راهنمای کامل و روش کار تنظیمات هوش مصنوعی (API مرکزی)

۱) این بخش چه کاری انجام می‌دهد؟

همهٔ تحلیل‌های هوش مصنوعی سامانه از همین یک نقطه تغذیه می‌شوند: توصیف خودکار ملک (نقاط قوت، نقاط ضعف و جمع‌بندی آماده برای فایل) و تحلیل عملکرد کارشناس (فروش، فعالیت و پیگیری‌ها). سامانه هیچ مدل داخلی ندارد و اطلاعات را به سرویس بیرونی‌ای می‌فرستد که شما در همین صفحه معرفی می‌کنید؛ سرویس باید با قالب استاندارد OpenAI Chat Completions سازگار باشد.

۲) روش کار، گام‌به‌گام

  1. فعال: کلید اصلی این قابلیت است. تا وقتی خاموش باشد هیچ درخواستی به سرویس بیرونی فرستاده نمی‌شود و دکمه‌های تحلیل در برنامه غیرفعال می‌مانند.
  2. نشانی پایهٔ سرویس (Base URL): نشانی عمومی و HTTPS سرویس را وارد کنید؛ مثلاً https://api.openai.com/v1. مسیر /chat/completions خودکار به این نشانی اضافه می‌شود؛ پس آن را دستی وارد نکنید. نشانی‌های http، لوکال‌هاست و آی‌پی‌های داخلی به دلایل امنیتی (جلوگیری از SSRF) پذیرفته نمی‌شوند.
  3. کلید API: کلید سرویس را یک بار وارد کنید. کلید با الگوریتم AES-GCM رمزنگاری و ذخیره می‌شود، بعد از ذخیره هرگز در صفحه نمایش داده نمی‌شود و برای حفظ کلید فعلی کافی است فیلد را خالی بگذارید. برای پاک کردن کلید، گزینهٔ «حذف کلید ذخیره‌شده» را فعال کنید.
  4. نام مدل: شناسهٔ دقیق مدل مطابق مستندات سرویس‌دهنده، مثلاً gpt-4o-mini. این فیلد همیشه الزامی است.
  5. ذخیره: پس از تکمیل مقادیر، فرم را ذخیره کنید. اعتبار نشانی، مدل و کلید ذخیره‌شده در همین مرحله بازبینی می‌شود.
  6. آزمون اتصال: دکمهٔ «آزمون اتصال به سرویس مرکزی» یک درخواست واقعی با کمترین توکن می‌فرستد و نتیجه را در همین صفحه و در فهرست این بخش گزارش می‌کند؛ اگر سرویس خطا برگرداند، متن خطا نمایش داده می‌شود.
  7. استفاده در برنامه: از این پس دکمه‌های تحلیل (صفحهٔ ملک، تحلیل کارشناس) نتایج را از همین سرویس می‌گیرند. نتیجهٔ هر تحلیل ۷ روز در سامانه نگه داشته می‌شود و با تغییر داده‌ها دوباره ساخته می‌شود؛ همچنین برای کنترل هزینه، سقف درخواست کاربران ۱۰ بار در ساعت است.

۳) درخواستی که سامانه می‌فرستد

سامانه با متد POST و هدرهای Authorization: Bearer <کلید> و Content-Type: application/json درخواست را به <نشانی پایه>/chat/completions می‌فرستد. بدنهٔ درخواست دقیقاً این ساختار است: 

{
  "model": "gpt-4o-mini",
  "messages": [
    {"role": "system", "content": "نقش و قالب خروجی مورد انتظار سامانه (فارسی)"},
    {"role": "user",   "content": "اطلاعات ملک یا عملکرد کارشناس به صورت JSON"}
  ],
  "temperature": 0.4,
  "max_tokens": 1400
}

هدر و بدنه در همین ساختار ارسال می‌شود؛ فقط model و مقدار کلید از تنظیمات همین صفحه خوانده می‌شوند. مهلت انتظار برای پاسخ نیز ۱۸۰ ثانیه است.

۴) خروجی مورد انتظار از مدل

پاسخ سرویس از مسیر choices[0].message.content خوانده می‌شود و باید متن JSON با این قالب باشد: سه نقطهٔ قوت، سه نقطهٔ ضعف و یک جمع‌بندی ۸۰ تا ۱۴۰ کلمه‌ای برای توصیف ملک (برای تحلیل کارشناس، همان ساختار با محتوای عملکرد). 

{
  "positives": ["نقطه قوت اول", "نقطه قوت دوم", "نقطه قوت سوم"],
  "negatives": ["نقطه ضعف اول", "نقطه ضعف دوم", "نقطه ضعف سوم"],
  "summary": "جمع‌بندی آمادهٔ انتشار دربارهٔ ملک یا عملکرد، بین ۸۰ تا ۱۴۰ کلمه"
}

اگر پاسخ مدل JSON معتبر نباشد یا کلید summary نداشته باشد، نتیجه نامعتبر تلقی می‌شود و پیام خطای مناسب به کاربر نشان داده می‌شود.

۵) نمونهٔ کامل و دقیق (سرویس OpenAI)

برای راه‌اندازی با OpenAI، دقیقاً این مقادیر را در فیلدهای بالا وارد کنید:

فیلد مقدار دقیق
فعال روشن
نشانی پایهٔ سرویس https://api.openai.com/v1
کلید API کلید حساب OpenAI؛ قالب نمونه: sk-proj-XXXXXXXX (کلید واقعی خود را بگذارید)
نام مدل gpt-4o-mini

سپس فرم را ذخیره کنید و دکمهٔ «آزمون اتصال به سرویس مرکزی» را بزنید. سرویس به نشانی زیر درخواست می‌فرستد: 

POST https://api.openai.com/v1/chat/completions
Authorization: Bearer sk-proj-XXXXXXXX
Content-Type: application/json

معادل خط فرمان همان درخواست (برای بررسی بیرون از سامانه) این است؛ در آن، sk-proj-XXXXXXXX را با کلید واقعی خود عوض کنید: 

curl https://api.openai.com/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer sk-proj-XXXXXXXX" \
  -d '{
    "model": "gpt-4o-mini",
    "messages": [{"role": "user", "content": "سلام"}],
    "temperature": 0.4,
    "max_tokens": 1400
  }'

پاسخ موفق سرویس چنین شکلی دارد:

{
  "id": "chatcmpl-...",
  "object": "chat.completion",
  "model": "gpt-4o-mini-2024-07-18",
  "choices": [
    {
      "index": 0,
      "message": {"role": "assistant", "content": "..."},
      "finish_reason": "stop"
    }
  ],
  "usage": {"prompt_tokens": 412, "completion_tokens": 268, "total_tokens": 680}
}

در آزمون اتصال، سامانه فقط این مسیر و دسترسی را می‌سنجد و انتظار دارد سرویس کد وضعیت 200 برگرداند و متن پاسخ غیرخالی باشد؛ در نتیجهٔ موفق، نام سرویس‌دهنده، نام مدل، زمان پاسخ (میلی‌ثانیه) و نمونهٔ متن بازگشتی نمایش داده می‌شود. برای تحلیل واقعی ملک یا کارشناس همان مسیر با پیام‌های کامل‌تر استفاده می‌شود و خروجی JSON بخش ۴ از دل پاسخ استخراج می‌گردد.

۶) جدول خلاصهٔ سرویس‌دهنده‌های سازگار

هر سرویسی که قالب OpenAI Chat Completions را پشتیبانی کند قابل استفاده است. چند نمونهٔ رایج از نشانی پایه و نام مدل:

سرویس‌دهنده نشانی پایه نمونهٔ نام مدل
OpenAI https://api.openai.com/v1 gpt-4o-mini
OpenRouter https://openrouter.ai/api/v1 openai/gpt-4o-mini
Google Gemini https://generativelanguage.googleapis.com/v1beta/openai gemini-2.0-flash
DeepSeek https://api.deepseek.com/v1 deepseek-chat
Groq https://api.groq.com/openai/v1 llama-3.3-70b-versatile
Mistral AI https://api.mistral.ai/v1 mistral-small-latest
Together AI https://api.together.xyz/v1 meta-llama/Llama-3.3-70B-Instruct-Turbo
سرویس اختصاصی سازگار با OpenAI نشانی HTTPS سازمان خودتان شناسهٔ مدل طبق مستندات همان سرویس

سرویس‌دهنده از نشانی پایه و نام مدل شناسایی می‌شود و نام آن در وضعیت همین بخش نمایش داده می‌شود؛ سرویس ناشناس با عنوان «سرویس سفارشی سازگار با OpenAI» گزارش می‌شود.

۷) خطاهای پرتکرار و راه‌حل

نشانه معنی و راه‌حل
کد وضعیت 401 یا 403 کلید API نادرست، منقضی یا نامرتبط است. کلید جدید را در فیلد کلید وارد و ذخیره کنید.
کد وضعیت 404 نشانی پایه درست نیست یا مسیر /chat/completions را دستی اضافه کرده‌اید. نشانی پایه را بدون آن مسیر وارد کنید.
کد وضعیت 400 یا 422 نام مدل نامعتبر است یا سرویس قالب پیام را نمی‌پذیرد. شناسهٔ مدل را از مستندات سرویس‌دهنده بردارید.
کد وضعیت 429 سقف مصرف یا تعداد درخواست سرویس پر شده است. اعتبار حساب سرویس‌دهنده را بررسی کنید.
کد وضعیت 5xx اختلال موقت سرویس‌دهنده است؛ چند دقیقه بعد آزمون را تکرار کنید.
پیام «اتصال برقرار نشد» دسترسی شبکه، فایروال سرور یا گواهی HTTPS سرویس‌دهنده را بررسی کنید.
پیام خطای نشانی غیرمجاز نشانی باید HTTPS و عمومی باشد؛ آدرس لوکال، شبکهٔ داخلی و آی‌پی خصوصی مسدود است.
پیام «کلید ذخیره‌شده قابل خواندن نیست» کلید رمزنگاری‌شده از تاریخچه حذف یا عوض شده است؛ کلید API را دوباره وارد و ذخیره کنید.

۸) نکات امنیتی و عملکردی

  • کلید API رمزنگاری‌شده ذخیره می‌شود و در پاسخ به مرورگر یا در صفحه‌های برنامه نمایش داده نمی‌شود.
  • ارسال داده فقط به نشانی HTTPS عمومی انجام می‌شود؛ نشانی‌های داخلی و ناامن رد می‌شوند.
  • دسترسی به این صفحه فقط برای کاربران مدیریتی دارای مجوز فهرست/تغییر تنظیمات شرکت ممکن است.
  • نتیجهٔ هر تحلیل تا ۷ روز اعتبار دارد؛ سقف درخواست‌های هوش مصنوعی برای هر کاربر ۱۰ بار در ساعت است.
  • تغییر کلید یا خاموش‌کردن سرویس، تنها از همین صفحه انجام می‌شود و بلافاصله روی همهٔ تحلیل‌های بعدی اثر می‌گذارد.
