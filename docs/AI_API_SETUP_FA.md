# راهنمای پیکربندی API هوش مصنوعی

این راهنما تنظیم سرویس تحلیل ملک و مشاور را از Django Admin شرح می‌دهد. سامانه از APIهای عمومی سازگار با قالب OpenAI Chat Completions استفاده می‌کند؛ آدرس سرویس، شناسه مدل و کلید محرمانه از یک محل مرکزی خوانده می‌شوند.

## پیش‌نیاز امنیتی

در محیط عملیاتی، کلید رمزنگاری باید مستقل از کلید Django باشد و فقط در متغیر محیطی سرور نگهداری شود. مقدار آن باید دقیقاً ۳۲ بایت تصادفی (۶۴ نویسه هگزادسیمال) باشد.

ساخت مقدار تصادفی برای کلید رمزنگاری و کلید Django در Linux، macOS یا PowerShell:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
python -c "import secrets; print(secrets.token_urlsafe(50))"
```

خروجی دستور اول را در `SECRET_ENCRYPTION_KEY` و خروجی دوم را در `DJANGO_SECRET_KEY` بگذارید.

نمونه تنظیمات محیطی سرور:

```dotenv
DJANGO_DEBUG=0
DJANGO_SECRET_KEY=<کلید-محرمانه-و-طولانی-جنگو>
SECRET_ENCRYPTION_KEY=<خروجی-۶۴-نویسه‌ای-دستور-بالا>
ALLOWED_HOSTS=crm.example.com
AI_REQUEST_TIMEOUT=180
```

مقدار واقعی کلیدها را در فایل نمونه، مخزن Git، تیکت یا پیام‌رسان قرار ندهید. آن‌ها را در تنظیمات امن سرویس میزبان نگهداری کنید. `SECRET_ENCRYPTION_KEY` نباید با `DJANGO_SECRET_KEY` یکی باشد.

در حالت توسعه (`DJANGO_DEBUG=1`)، اگر کلید اختصاصی تنظیم نشده باشد، برنامه از کلید Django برای رمزنگاری محلی استفاده می‌کند. این حالت برای سرور عملیاتی مناسب نیست؛ هنگام `DJANGO_DEBUG=0` تنظیم `SECRET_ENCRYPTION_KEY` الزامی است. برنامه مقدار نامعتبر یا کلید با طول نادرست را رد می‌کند.

کلید API در پایگاه داده به‌صورت AES-256-GCM و با nonce تصادفی رمز می‌شود. فرم Admin آن را بازنمایی نمی‌کند: خالی گذاشتن فیلد، کلید قبلی را حفظ می‌کند؛ برای جایگزینی مقدار تازه را وارد کنید و برای حذف، گزینهٔ «حذف کلید ذخیره‌شده» را فعال کنید. رمزگشایی به همان `SECRET_ENCRYPTION_KEY` نیاز دارد؛ آن را در کنار نسخهٔ پشتیبان پایگاه داده، اما جدا از خود نسخهٔ پشتیبان، امن نگه دارید. تغییر یا گم‌شدن این کلید بدون فرایند چرخش کلید، دسترسی به کلید API ذخیره‌شده را از بین می‌برد.

## نصب و ارتقا

در ریشهٔ پروژه:

```bash
cd ZaminexB
pip install -r requirements.txt
python manage.py migrate
```

پس از تغییر متغیرهای محیطی، فرایند Django را دوباره راه‌اندازی کنید. نسخه‌های قدیمی کلید که با قالب `enc:v1` ذخیره شده‌اند قابل خواندن هستند و با ذخیرهٔ تنظیمات دوباره، به قالب امن‌تر `enc:v2` ارتقا می‌یابند. اگر کلید قدیمی با متغیر جداگانه‌ای تنظیم شده بود، همان مقدار قدیمی را تا پایان ارتقا حفظ کنید.

## تنظیم از Django Admin

1. با حساب دارای دسترسی مدیریت وارد `/admin/` شوید.
2. بخش **تنظیمات شرکت** را باز کنید؛ تنظیمات API به همان رکورد مرکزی متصل است.
3. در گروه **هوش مصنوعی (API)** فیلدها را مطابق سرویس‌دهنده تکمیل کنید.
4. گزینهٔ **فعال‌سازی هوش مصنوعی** را فعال و فرم را ذخیره کنید.

نام مدل همیشه الزامی است؛ اگر سرویس را فعال کنید، نشانی پایه نیز الزامی خواهد بود. کلید API برای سرویس‌هایی که احراز هویت نمی‌خواهند اختیاری است.

### نمونهٔ دقیق: OpenAI

| فیلد Admin | مقدار نمونه |
|---|---|
| فعال‌سازی هوش مصنوعی | فعال |
| آدرس پایه API | `https://api.openai.com/v1` |
| نام مدل | `gpt-4o-mini` |
| کلید API | کلید محرمانه‌ای که از پنل سرویس‌دهنده گرفته‌اید؛ آن را در مستندات یا مخزن ننویسید |

سامانه مسیر `/chat/completions` را خودکار به آدرس پایه می‌افزاید؛ بنابراین نشانی کامل درخواست در این نمونه چنین است:

```text
https://api.openai.com/v1/chat/completions
```

در فیلد آدرس پایه، مسیر کامل `chat/completions` را ننویسید. برای سرویس‌دهندهٔ دیگری، مقدار پایه و شناسهٔ مدل را دقیقاً مطابق مستندات خودش و با همین قرارداد وارد کنید. برای نمونه، یک سرویس DeepSeek سازگار می‌تواند از `https://api.deepseek.com` و مدل `deepseek-chat` استفاده کند.

آدرس باید HTTPS و میزبان عمومی معتبر باشد. برای جلوگیری از درخواست به شبکهٔ داخلی (SSRF)، نشانی‌های HTTP، `localhost`، IP خصوصی و میزبان‌هایی که به IP خصوصی ترجمه شوند پذیرفته نمی‌شوند؛ سرویس محلی یا بدون TLS قابل استفاده نیست.

## قرارداد درخواست و پاسخ

سامانه درخواست `POST` با هدر `Content-Type: application/json` می‌فرستد و در صورت وجود کلید، هدر `Authorization: Bearer …` را اضافه می‌کند. شکل کلی بدنه چنین است:

```json
{
  "model": "gpt-4o-mini",
  "messages": [
    {"role": "system", "content": "دستور تحلیل فارسی و قالب پاسخ JSON"},
    {"role": "user", "content": "داده‌ها و درخواست تحلیل ملک یا مشاور"}
  ],
  "temperature": 0.4,
  "max_tokens": 1400
}
```

پاسخ سرویس باید قالب متداول Chat Completions را داشته باشد؛ متن پاسخ مدل باید یک شیء JSON با این کلیدها باشد:

```json
{
  "positives": ["نکته مثبت اول", "نکته مثبت دوم", "نکته مثبت سوم"],
  "negatives": ["نکته منفی اول", "نکته منفی دوم", "نکته منفی سوم"],
  "summary": "یک بند فارسی حرفه‌ای بر پایه داده‌های همان رکورد"
}
```

سامانه متن را از `choices[0].message.content` می‌خواند و تعدادی از قالب‌های رایج پاسخ سازگار را نیز می‌پذیرد. پاسخ باید JSON معتبر و شامل داده‌های واقعی باشد؛ مدل نباید شاخص یا اطلاعاتی را که در درخواست نیست حدس بزند. برای سرویس OpenAI، آزمون مستقل دسترسی و کلید (بدون قرار دادن کلید واقعی در تاریخچهٔ خط فرمان) با این درخواست انجام می‌شود:

```bash
curl --silent --show-error --fail https://api.openai.com/v1/chat/completions \
  -H "Authorization: Bearer ${OPENAI_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-4o-mini",
    "messages": [
      {"role": "user", "content": "Return only JSON: {\"ok\": true}"}
    ],
    "temperature": 0,
    "max_tokens": 30
  }'
```

مقدار `OPENAI_API_KEY` را در محیط امن همان نشست تنظیم کنید؛ کلید را مستقیماً در دستور ننویسید، چون ممکن است در تاریخچهٔ پوسته ثبت شود.

## داده‌های ارسالی و نگهداری

برای تحلیل، سرور شاخص‌ها و نمودارهای تجمیعی همان رکورد را همراه با مشخصات لازم می‌فرستد. در تحلیل مشاور، نام، شعبه و شاخص‌های کاری استفاده می‌شوند؛ در تحلیل ملک، عنوان، کد داخلی، محله، وضعیت، متراژ، تعداد اتاق، شاخص‌های بازار و داده‌های گزارش‌شدهٔ همان ملک استفاده می‌شوند. پیش از فعال‌سازی، سیاست محرمانگی سازمان و شرایط سرویس‌دهنده را بررسی کنید؛ ارسال درخواست به سرویس‌دهندهٔ خارجی، داده را از زیرساخت سازمان خارج می‌کند.

خروجی تحلیل برای کاهش درخواست‌های تکراری به‌صورت موقت در سامانه ذخیره می‌شود و عمر کش آن هفت روز است. کلید API در لاگ برنامه قرار داده نمی‌شود و در فرم مدیریت نمایش داده نمی‌شود.

## خطایابی

- **قابلیت غیرفعال است:** گزینهٔ فعال‌سازی را در تنظیمات شرکت بررسی کنید.
- **خطای اتصال یا پاسخ ۵۰۲/۵۰۳:** دسترسی خروجی سرور، نشانی پایه، شناسهٔ مدل، اعتبار کلید و سازگاری پاسخ را بررسی کنید. مقدار پیش‌فرض مهلت درخواست ۱۸۰ ثانیه است؛ در صورت نیاز `AI_REQUEST_TIMEOUT` را در محیط سرور تغییر دهید.
- **نشانی رد می‌شود:** فقط از HTTPS عمومی استفاده کنید و مطمئن شوید DNS دامنه به IP عمومی ترجمه می‌شود.
- **کلید ذخیره‌شده رمزگشایی نمی‌شود:** مقدار `SECRET_ENCRYPTION_KEY` باید با مقداری که زمان ذخیرهٔ کلید استفاده شده برابر باشد. کلید درست را از تنظیمات امن سرور بازیابی کنید؛ کلید API را دوباره وارد کردن، خطای رمزگشایی تنظیم قبلی را برطرف نمی‌کند.
- **مدل در Admin پذیرفته نمی‌شود:** نام مدل را دقیقاً طبق پنل سرویس‌دهنده وارد کنید و از فاصلهٔ ابتدا یا انتهای مقدار پرهیز کنید.
- **مدل پاسخ غیرقابل‌خواندن می‌دهد:** سرویس باید پاسخ سازگار با Chat Completions و محتوای JSON معتبر برگرداند.
